# Измеритель скорости загрузки HTTP-ресурса

Небольшая консольная программа принимает URL большого HTTP-ресурса, выполняет
10 последовательных загрузок, полностью читает тело каждого ответа и измеряет
длительность каждой попытки. По фактически полученным данным программа рассчитывает
общий объём и среднюю пропускную способность HTTP-загрузки.

Это utility для измерения application-level HTTP download throughput до конкретного
сервера и ресурса. Результат зависит от выбранного сервера, маршрута, HTTP/TLS,
redirect и способа отдачи файла; программа не является полноценной заменой
специализированному ISP speed-test сервису.

## Требования

- Python 3.12 или новее;
- [uv](https://docs.astral.sh/uv/).

Make можно использовать как необязательный удобный интерфейс для команд разработки.
Для установки, запуска приложения и всех проверок Make не требуется: доступны прямые
команды `uv`.

## Установка

```console
git clone https://github.com/victorrusskikh96-byte/internet-speed-meter.git
cd Speed_Testester_testTask
uv sync
```

`uv` самостоятельно создаст и синхронизирует локальное окружение.

## Запуск приложения

Передайте один абсолютный HTTP- или HTTPS-URL большого ресурса:

```console
uv run internet-speed-meter "https://example.com/path/to/large-file.bin"
```

URL в примере является условным: для содержательного измерения выберите доступный
вам достаточно большой ресурс. 
ВАЖНО: URL должен быть в "кавычках".
Фрагмент URL удаляется до запроса. Программа следует
HTTP redirect, включая переходы между HTTP и HTTPS, но ограничивает одну цепочку
20 переходами.

## Пример успешного вывода

```text

Запрос 2/10: 0.200 с, 200000 байт
Запрос 3/10: 0.300 с, 300000 байт
Запрос 4/10: 0.400 с, 400000 байт
Запрос 5/10: 0.500 с, 500000 байт
Запрос 6/10: 0.600 с, 600000 байт
Запрос 7/10: 0.700 с, 700000 байт
Запрос 8/10: 0.800 с, 800000 байт
Запрос 9/10: 0.900 с, 900000 байт
Запрос 10/10: 1.000 с, 1000000 байт

Скачано: 5500000 байт (5.500 MB)
Средняя скорость: 1.000 MB/s (8.000 Mbps)
```

Значения приведены только как пример формата; фактический результат зависит от сети
и ресурса.

## Как работает измерение

1. Выполняются ровно 10 HTTP GET-запросов к одному URL.
2. Запросы идут строго последовательно: следующий начинается только после полного
   завершения предыдущего.
3. Тело каждого ответа полностью читается, а число фактически полученных необработанных bytes
   считается напрямую, без опоры на `Content-Length`.
4. Для каждого запроса измеряется время от начала отправки до полного чтения тела.
5. Среднее время запроса — арифметическое среднее десяти длительностей.
6. Общий объём — сумма фактически полученных bytes всех конечных ответов.
7. Итоговый throughput вычисляется как `total bytes / total measured duration`.

Итоговый throughput не является простым арифметическим средним скоростей отдельных
запросов. Все десятичные значения округляются только при выводе.

## Единицы измерения

- 1 MB = 1 000 000 bytes;
- MB/s — мегабайты в секунду;
- Mbps — мегабиты в секунду;
- 1 byte = 8 bits.

## Обработка ошибок

До сетевого обращения программа отклоняет некорректный URL, относительный URL и
схемы, отличные от HTTP/HTTPS. Во время измерения обрабатываются HTTP 4xx/5xx,
30-секундный timeout бездействия, ошибки соединения и другие ожидаемые сетевые
ошибки. При первой ошибке измерение прекращается без retries и успешного итогового
блока. Ожидаемые ошибки завершают программу с ненулевым exit code.

## Команды разработки

Makefile предоставляет короткие команды поверх `uv`:

```console
make install
make format
make format-check
make lint
make typecheck
make test
make check
```

Запуск приложения через Make требует явного URL:

```console
make run URL=https://example.com/path/to/large-file.bin
```

Те же операции доступны напрямую и подходят для Windows, где Make может отсутствовать:

```console
uv sync
uv run ruff format .
uv run ruff format --check .
uv run ruff check .
uv run mypy src
uv run pytest
```

Полный локальный quality gate без Make состоит из четырёх последних проверочных команд:
format check, lint, type check и tests.
